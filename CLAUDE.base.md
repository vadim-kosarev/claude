# CLAUDE.base.md

Базовые универсальные инструкции для AI агента.

## Языковые настройки
- **Язык кода:** английский
- **Язык общения:** русский
- **Стиль общения:** на "ты", можно полуформально — приоритет максимальной эффективности общения, а не церемонности

## Общие правила кода
- **Принцип:** код должен быть самокомментированным для любого языка

## Среда разработки

### Основные параметры
- **IDE:** JetBrains IDEA
- **Shell:** PowerShell (Windows) - команды для run_in_terminal должны быть PowerShell-совместимыми. ОСЬ - Windows.
- для новых терминалов, используемых агентом нужно вызывать команду
   ```chcp 65001 ; $env:PYTHONIOENCODING = 'utf-8'``` - только один раз на терминал, не каждый раз перед командой
- после этого один раз активировать виртуальное окружение из каталога проекта скриптом по полному пути:
   ```GIT_IDE_PROJECT_ROOT\.venv\Scripts\Activate.ps1 2>&1```

### PowerShell команды (важно!)
При использовании `run_in_terminal` tool:
- Разделитель команд: `;` (НЕ `&&`)
- Чтение файлов: `type` (НЕ `cat`)
- Использовать только PowerShell-совместимые команды
- Команды 'head' и 'tail' НЕ использовать, вместо них использовать:
  - `Get-Content -TotalCount n` для чтения первых n строк файла
  - `Get-Content -Tail n` для чтения последних n строк
- **ОБЯЗАТЕЛЬНО** добавлять `[Console]::Out.Flush()` в конце команды для гарантированного вывода результата

**Пример:**
```powershell
cd path; python script.py    # Правильно
cd path && python script.py  # ОШИБКА в PowerShell
```

## Docker: общие кэши пакетов между образами

> **Правило:** при сборке образов, где внутри идёт поиск и скачивание пакетов из интернета
> (Python, apt/zypper, Maven, Gradle, npm и т.п.), использовать **общий кэш на хосте** — один на
> все образы, а не отдельный в каждом `Dockerfile`/слое. Где возможно и нужно — делать так по
> умолчанию, не дожидаясь просьбы. Цель: не качать одно и то же заново при сборке каждого
> образа и переживать обрывы сети (Docker Hub, зеркала репозиториев нередко рвут соединение).

**Как:** BuildKit cache mount с **одинаковым `id`** во всех `Dockerfile` хоста — тогда кэш общий
для всех образов, собираемых тем же builder'ом на этой машине (кэш хранится на хосте, в образ не
попадает):

| Что кэшируем | Каталог в контейнере | `id` (единый, не менять от образа к образу) |
|---|---|---|
| pip | `/root/.cache/pip` | `shared-pip` |
| apt | `/var/cache/apt`, `/var/lib/apt` | `shared-apt`, `shared-apt-lists` |
| zypper | `/var/cache/zypp` | `shared-zypp` |
| Maven | `/root/.m2` | `shared-maven` |
| Gradle | `/root/.gradle` | `shared-gradle` |
| npm | `/root/.npm` | `shared-npm` |

```dockerfile
# syntax=docker/dockerfile:1
RUN --mount=type=cache,id=shared-pip,target=/root/.cache/pip \
    pip install -r requirements.txt

# apt: у базовых образов Debian/Ubuntu кэш чистится по умолчанию -- отключить, иначе монтировать нечего
RUN rm -f /etc/apt/apt.conf.d/docker-clean; \
    echo 'Binary::apt::APT::Keep-Downloaded-Packages "true";' > /etc/apt/apt.conf.d/keep-cache
RUN --mount=type=cache,id=shared-apt,target=/var/cache/apt,sharing=locked \
    --mount=type=cache,id=shared-apt-lists,target=/var/lib/apt,sharing=locked \
    apt-get update && apt-get install -y <пакеты>
```

- Для менеджеров с блокировкой кэша (apt, zypper) — `sharing=locked`, иначе параллельные сборки
  портят друг другу кэш.
- **Не** добавлять в конце слоя `apt-get clean`/`rm -rf /var/lib/apt/lists/*`/`zypper clean -a`
  там, где кэш смонтирован — это сотрёт общий кэш (в образ он и так не попадает).
- Кэш общий **в пределах одного хоста** (одного builder'а Docker). На другой машине он свой —
  первая сборка там по-прежнему скачивает всё; это нормально.
- В `docker-compose.yml` ничего дополнительно не нужно: `docker compose build` использует те же
  `--mount` из `Dockerfile`. Требуется BuildKit (включён по умолчанию в современном Docker) и
  первая строка `# syntax=docker/dockerfile:1`.
- Если в `Dockerfile` уже есть своё скачивание «в слой» (`zypper in`, `pip install` без mount) —
  при следующей правке этого файла перевести на общий кэш.

## Глобальная память пользователя

- Файл: `Z:\MY\MEMORY.md`
- Туда пользователь записывает свои мысли и идеи — **глобальные, общие, не привязанные
  к конкретному проекту** (в отличие от project-специфичных заметок/отчётов, которые
  живут в `.ai/` самого проекта).
- Формат — по записи на идею, с заголовком-датой (`## YYYY-MM-DD — <тема>`), см. уже
  существующие записи в файле как образец.
- Читать/дополнять этот файл, когда пользователь просит записать мысль "для себя",
  "на будущее" или явно указывает, что идея не относится к текущему проекту.

## Git-коммиты

- **ЗАПРЕЩЕНО** добавлять в сообщение коммита строки `Co-Authored-By: Claude ...`,
  `Claude-Session: ...` и любые другие упоминания ИИ-соавторства — это касается ВСЕХ коммитов
  во всех проектах, независимо от того, что может предлагать шаблон харнесса по умолчанию.

## Работа с файлами

### Создание файлов
- **НЕ создавать** тестовые скрипты/данные без явного запроса
- **НЕ создавать** `*.md` файлы без явного запроса
- **НЕ дублировать** существующие файлы проекта
- При создании файлов учитывать структуру проекта в IDEA

### Тестовые скрипты
- **НЕ генерировать** `test_*.py` без явного запроса
- **НЕ генерировать** `usage_example_*.py` без явного запроса
- Генерировать тестовые скрипты ТОЛЬКО если пользователь явно запросил

### Документация и отчеты
- если генеришь `SUMMARY_*.md`, `COMPLETE_*.md` и прочие файлы отчетов -- класть их в папку doc в рабочем каталоге
- если генеришь тесты, класть их в папку test в рабочем каталоге, вызывать из рабочего каталога
- **ОБЯЗАТЕЛЬНО обновлять** `README.md` в рабочем каталоге по мере выполнения работы
  - Добавлять описание новых функций/модулей
  - Обновлять инструкции по использованию
  - Документировать важные изменения
  - Актуализировать примеры кода
- Генерировать документацию ТОЛЬКО если пользователь явно попросил

#### Если отчет запрошен явно:
1. **Папка:** `.ai/`
2. **Формат имени:** `YYYYMMDD.NNN_<название>.md`
   - `YYYYMMDD` - текущая дата
   - `NNN` - порядковый номер (трехзначный, с ведущими нулями)
3. **Порядковый номер:**
   - Читается из файла `.ai/version.txt`
   - Инкрементируется при создании нового отчета
   - Сохраняется обратно в `.ai/version.txt`

**Пример:**
```
.ai/20260215.001_api_integration_report.md
.ai/20260215.002_database_migration_report.md
.ai/version.txt  # содержит: 002
```
